API Gateway Refactor Draft

This document outlines the proposed changes for migrating our current monolithic API gateway to a federated GraphQL approach using Apollo Federation.

Objectives

  • Decouple domain services from the edge gateway layer.
  • Improve independent deployability for the `users`, `payments`, and `inventory` subgraphs.
  • Reduce the latency overhead introduced by REST-to-GraphQL translation layers.

Current Bottlenecks

The existing Node.js express gateway has become a bottleneck for deployment. Every schema change requires a synchronized deployment of the gateway, which violates our microservices autonomy principles.

// Current tightly coupled router
router.use('/api/v1/users', createProxyMiddleware({ target: process.env.USER_SERVICE_URL }));
router.use('/api/v1/payments', createProxyMiddleware({ target: process.env.PAYMENT_SERVICE_URL }));
